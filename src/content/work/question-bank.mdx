## The problem

Questions lived inside each survey, so admins rebuilt the same questions repeatedly and translations drifted.

Demographic questions used an older, separate model that reports depended on. Customers couldn't translate or edit those questions themselves: it all went through Support, often with Engineering. A customer running 21 languages across 10 such questions could need over 1,000 translations handled that way.

Customers couldn't edit a demographic question at all once it was created, so a routine yearly update, such as changing a question's options, meant rebuilding it or asking Support. The questions also needed bringing up to date with current accessibility and inclusion practice.

## What I did

- A per-organisation MongoDB model using Mongoose discriminators, plus global questions shared by everyone.
- GraphQL create, update, archive and delete, and a React editor tuned to avoid needless re-renders.
- Machine translation that only fills empty languages, so human translations are never overwritten.
- Migrated the legacy demographic questions in, rewrote historic survey components to the new shape, and kept old and new formats running side by side during rollout, then deleted the old code paths (~10k lines).
- Added an index once real data showed a lookup was slow.
