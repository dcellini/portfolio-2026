## The problem

Onboarding and exit surveys only work if the right people get them at the right time. Admins had to add every new starter and leaver by hand.

As more organisations used onboarding and exit surveys, that manual step became a real bottleneck for medium and large organisations. Automating it became the most common follow-up request from customers.

## What I did

- Wrote the RFC covering the architecture, data schemas and end-to-end flow, then a detailed implementation spec.
- Designed rule-based audiences, for example "joined in the last 30 days, in these departments", and a model that lets one survey have several distribution lists.
- Split the build into a stack of about 16 reviewable pull requests across 10 packages: shared contracts, a new service, a scheduled trigger, changes to the survey and user services, GraphQL, and a five-part front end.
- Designed the rule builder and recipients tab myself, end to end, with no design input.
- Deployed the full stack to a development environment and fixed the infrastructure gaps that exposed.
