## The problem

Employees relied on email to do almost anything on Hive: submitting a survey, sending feedback or giving recognition all started with finding the right email. Those emails were easily deleted and arrived irregularly, and employees without an email address had no way in at all.

On recognition, employees could only see the recognitions they'd received, never the ones they'd given.

The plan was a single, always-on homepage for employees, starting with a recognition board showing both given and received as the foundation for a broader employee dashboard.

## What I did

- Added a block to the employee homepage with simple menu items linking to recognition features.
- Built a new recognitions endpoint on MongoDB Atlas Search and the GraphQL query behind it.
- Added a feed page for the recognitions you've sent.
- Fixed the sent-recognition update mutation and simplified the list endpoint.
- Hid the surveys block entirely when an employee has no surveys to complete.
- Replaced the old block with new homepage navigation and a recognitions feed, then refactored the employee header and retired the old block, released incrementally behind a feature flag.
- Added a user settings menu to the homepage.
- Translated the empty-state messages and fixed a redirect when validation failed.
